# 고정 몸 · 공용 골격 생산

`/avatar.html?stage=standard`에서 사용한다. 기존 이미지 공장 상단의 **고정 몸 · 공용 골격** 링크로 들어간다. 기존 공통 템플릿 변환과 별도로, 실제 입력 몸의 골격을 기준으로 파츠를 연결하는 로컬 작업 경로다.

## 사용 순서

1. 라이브러리에서 만든 Meshy 리깅 결과 또는 자체 포함 GLB를 기준 몸으로 등록한다. 실제 동작이 포함된 하나의 armature가 필요하다. 대머리·완전한 두피와 몸·중립 A-pose 여부는 아래 검수에서 확인한다.
2. 기준 몸의 정면·측면·후면과 동작을 확인하고 해당 해시를 승인한다. 기본 높이는 1.20m다. 원본 GLB는 보존하고, 전체 장면 위에 균일한 단위 변환을 추가한다. 원본 BIN, skin, inverse bind, UV, morph, animation channel은 변경하지 않는다. 특정 뼈 수나 본 이름으로 바꾸지 않는다.
3. 그 몸의 2048×2048 정사영 렌더를 기준으로 파츠 시안을 만든다. 정수리 y=300, 발바닥 y=1800, 중심 x=1024, 기본 배율 1250px/m다. 세 시점 모두 같은 배율이다. **Sunburst 시안 생성 · 유료 1회**는 선택한 시점의 몸 렌더를 첫 참고 이미지로 사용한다. 원래 캐릭터 PNG와 같은 파츠의 다른 시점도 참조할 수 있다. 입력 몸의 rest pose를 사용하므로 T-pose를 자동으로 A-pose로 고치지는 않는다.
4. 생성 시안과 몸 렌더에서 서로 대응하는 착용점 3개 이상을 클릭하거나 좌표로 입력한다. 측정한 점으로 이동·회전·균일 배율을 계산하고, 기본 8px 오차를 넘으면 디자인 수정 대상으로 돌린다. 파츠만 포함됐는지와 같은 디자인인지 확인한 뒤 정렬본을 저장한다. 외부에서 만든 2048px PNG도 업로드할 수 있다. 원본 캔버스를 보존하고, 선택한 crop의 위치·가로세로·확대 배율·출력 여백·실제 축소 결과 크기·미터 환산 범위를 저장한다. 생성용 이미지는 비율을 유지한 1024px 정사각형 PNG로 별도 출력한다.
5. 저장한 동일 물체의 시점을 선택해 **Meshy 7 파츠 생성 · 유료 1회**를 실행한다. 기존 작업 조회·다운로드 후 생성한 형상을 선택하거나 외부 GLB를 가져올 수 있다. 대응하는 착용 기준점 3개 이상을 입력한다. `source`는 파츠 파일, `target`은 기준 몸 좌표다. 좌표는 glTF X 오른쪽/Y 위/Z 앞, 미터 단위다. 비공선 점이어야 한다. 목·좌우 어깨처럼 착용부를 지정하며 장식의 외곽 폭을 규격으로 강제하지 않는다.
6. 상의·바지·부츠는 몸의 삼각형 표면에서 barycentric 가중치를 전달한다. 짧은 헤어·모자·단단한 신발·소품은 지정한 기존 본에 연결한다. 좌우 신발은 각각 저장한다. 치마는 골반 등 지정 본에 연결하는 단단한 파츠 경로이며 천 시뮬레이션은 없다.
7. **옷 갈아입기**에서 슬롯별 파츠를 선택하면 동작을 재생하는 몸을 유지한 채 의상만 바뀐다. **현재 착용 저장**은 선택을 저장하며 새로고침 후 복원한다. 별도의 **선택한 파츠로 조합 저장**은 GLB·BLEND와 정면/측면/후면/동작 증거를 새 버전으로 만든다. 한 슬롯에는 하나만 선택한다. R3F·WebGPU·gaesup-world 미리보기에서 원본 동작을 재생하며 호환 렌더러가 사용되면 표시한다.
8. 기준 몸과 선택한 파츠의 UV가 있는 재질은 조합 시 PNG를 교체할 수 있다. 내려받을 수 있는 재질별 `body-uv-*.svg`·`part-uv-*.svg`에 맞춰 얼굴 표정이나 의상 무늬를 만든다. 같은 UV 배치라는 확인이 필요하다. 정면 얼굴 그림을 자동으로 UV로 투영하는 기능은 아니다. 메시·골격·가중치를 그대로 쓰고 새 텍스처만 추가한다. 기존 morph는 보존하지만 새 표정 morph 제작·편집기는 없다.

## 피팅과 검수 경계

기준점 대응으로 회전·이동·균일 배율을 계산한다. 임의의 축별 늘이기로 전체 외형을 왜곡하지 않는다. 대응점 최대 오차가 허용값(기본 2cm)을 넘으면 실패한다. 가중치 전달도 몸 표면으로부터 허용 거리(기본 12cm)를 넘으면 실패한다. 이는 **착용 기준점 정렬과 공용 스킨 연결**이다. 잘못 그린 어깨/소매를 자동으로 재설계하거나 임의 의상의 안쪽 두께를 복원하는 기능은 아니다.

표면 거리와 관통 의심 정점 수를 기록하지만 열린 표면·옷 안쪽·복잡한 접합부에서 법선 기반 부호는 정확한 충돌 판정이 아니다. 실제 동작별 관통과 변형은 검수해야 한다. 애니메이션의 여러 시점에서 유한한 본 행렬과 움직임을 확인하고 진단 이미지를 만들며, 브라우저에서 파츠 정점 움직임과 공통 bone 참조를 별도로 검증한다.

몸 승인과 파츠/조합 기술 통과는 별개다. 파츠와 조합은 `review_required`이며 출시 승인 에셋으로 자동 등록하지 않는다. 새 경로는 임의 골격을 지원하므로 기존 23본 옷장 카탈로그에 강제로 넣지 않는다. 저장된 조합 선택·GLB 재생·내려받기는 새 화면에서 한다.

## 제공자와 비용

이 경로의 등록·피팅·조합·시안 crop에는 유료 제공자 호출이 없다. 몸 생성·리깅은 기존 캐릭터 라이브러리 경로를 사용할 수 있다. 파츠 형상 생성 버튼은 저장한 시점으로 Meshy 7 Multi-Image API에 1회 제출한다. 제공자 base·모델·시안 해시를 수락 시 고정하고 공통 `character_jobs` 어댑터가 POST 전 제출 의도를 저장한다. 불확실한 응답은 기존 task ID 복구만 허용하고 자동 재제출·파츠 리깅·모델 대체는 없다. 새로고침 후 조회·다운로드를 이어갈 수 있고 완료한 형상을 파츠 피팅 폼에서 직접 선택한다.

시안 생성은 OpenAI `gpt-image-2.5-sunburst` Images Edit API를 사용한다. 몸 렌더·참고 이미지·모델·제공자 주소·지시문을 수락 시 고정하고 `n=1`로 한 번만 요청한다. 제공자 원본과 2048px 정규화본을 모두 보존한다. 생성된 시안은 착용점 검수를 거치기 전에는 Meshy 입력으로 넘기지 않는다. 시간 초과·거절·응답 유실 후 모델 대체나 재요청은 하지 않으며, 이미 받은 바이트의 로컬 저장만 복구한다. 기존 이미지 공장의 프로필과 이 경로의 고정 몸 템플릿은 별개다.

다중 이미지 입력을 구성할 때는 같은 `object_key`, 같은 기준 몸 해시, 중복 없는 시점, 정면 우선 조건을 검사한다. Meshy의 [Multi-Image API](https://docs.meshy.ai/en/api/multi-image-to-3d)는 동일 물체의 서로 다른 시점 1~4장을 받으며 Meshy 7에서 첫 이미지가 정면이다. [Rigging API](https://docs.meshy.ai/en/api/rigging)의 독립 리깅을 파츠마다 실행하지 않는다.

## 저장·복구·검증

- 저장 위치: 데이터 루트 `avatar-standard/<owner>/<version>/`. 서버가 소유권을 검사하고 브라우저에는 서버 경로를 받거나 공개하지 않는다. DB schema 변경은 없다.
- 원본·입력·결과·해시 영수증을 버전별로 보존한다. 같은 idempotency key에는 같은 작업을 반환하며 입력이 바뀌면 충돌로 응답한다.
- 창을 닫아도 서버가 실행한다. 새로고침하면 목록·선택한 버전·상태를 복원한다. 요청 응답을 잃으면 같은 key로 복구한다.
- 서버 중단 후에는 서버와 전용 Blender 프로세스의 종료 여부를 확인한다. 프로세스가 살아 있거나 불명확하면 다시 실행하지 않는다. 완료 영수증이 유효하면 복구하고, 없으면 실패로 보존한다. 새 로컬 시도는 새 버전으로 만든다.
- `uv run pytest -q` — 소유권·중복 요청·검수 해시·이미지 좌표·업로드/입력 검증·중단 복구, 제공자 요청 상한·응답 유실·task 복구와 기존 경로. 제공자 응답은 대체하므로 실제 유료 생성 성공의 증거는 아니다.
- `uv run python backend/tests/run_avatar_standard_check.py` — 폐기 가능한 자체 제작 24본 fixture. 원본 skin/BIN/동작 보존, 실제 Blender 2048px 좌표 검사, 스킨 전달/단일 본 부착, 두 조합, UV 재질 변경, GLB/BLEND/렌더와 동작 중복 검사. 실제 Meshy 결과나 캐릭터 시각 승인이 아니다.
- 위 명령이 출력한 root를 `WORKSPACE_TEST_STANDARD_ROOT`로 지정하고 `frontend/`에서 `npm run test:e2e` — 실제 API·재연결·새로고침·골격 공유·정점 움직임·시안 측정점 정렬 검증. 제공자 키가 비어 있는 임시 서버를 사용한다.
- `frontend/`의 `npm run build`, `backend/`의 `uv run python tests/run_blender_parts_check.py` — 빌드와 기존 분리 회귀 확인.

착용점은 화면의 예시 숫자를 그대로 수락해서는 안 된다. 해당 파츠와 기준 몸에서 측정한 좌표를 사용한다. 기준 몸이나 파일 해시가 바뀌면 이전 파츠를 새 몸에 호환된 것으로 취급하지 않는다.

## 의상 배치와 Meshy 기준 몸

`/avatar.html?stage=standard`의 의상 일괄 생산은 승인한 몸 하나와 참고할 캐릭터 원본 이미지, 의상 목록(최대 16개)을 고정한다. 선택한 원본과 몸 렌더를 참고해 의상 시안을 만든 뒤 그 시안을 Meshy 3D 입력으로 사용한다. 같은 슬롯에 여러 종류를 등록할 수 있으며, 서로 다른 시점을 여러 의상으로 오인하여 하나의 Meshy 모델로 합치지 않는다. 각 의상은 Sunburst 시안 최대 1회와 Meshy 7 형상 최대 1회만 사용하고 추가 리깅은 하지 않는다.

- `POST /api/avatar-standard/batches`: 몸 ID·해시, 참고 PNG의 `reference_asset`, 의상 이름·슬롯·형태·설명, 요청 상한을 저장하고 각 시안을 실행한다. 모델·제공자 주소도 내부 기록에 고정한다. 이전 API 요청과의 호환성을 위해 참고 이미지는 선택 필드이며, 새 화면에서는 원본을 선택한다.
- 원본 PNG는 바이트를 그대로 업로드하고 SHA-256을 확인한다. 배치는 소유권을 확인한 참고 사본을 보존하고 모든 의상 시안에 전달한다. `GET /api/avatar-standard/batches/{id}/reference`는 그 배치에 고정한 이미지를 반환한다. 원본이나 사본 해시가 바뀌면 제공자 호출 전에 중단한다.
- `GET /api/avatar-standard/batches` 및 `/{id}`: 항목별 시안·형상·맞춤 파츠·오류를 반환한다. 새로고침 후에도 같은 배치를 표시한다.
- `POST /api/avatar-standard/batches/{id}/resume`: 정렬된 시안을 가진 항목을 일괄 Meshy 생성·조회·다운로드한다. 아직 정렬되지 않은 항목과 불확실한 제출은 별도로 남긴다. 한 항목의 오류로 다른 항목을 취소하지 않는다.
- 저장 경로는 `avatar-standard/<owner>/batches/<id>/`이며 의상별 자식 작업은 기존 버전 폴더에 유지한다. 응답을 잃은 수락 요청은 같은 idempotency key로 복구한다.
- 생성 시안의 착용점 정렬과 생성 형상의 측정·피팅은 현재 검수 단계다. 배치 생성만으로 자동 맞춤·완성 옷장으로 표시하지 않는다. 같은 배치의 형상에 연결된 파츠를 찾아 맞춤 완료 수를 갱신한다.

공장 Meshy 결과는 `BaseInput.factory_job_id`·`factory_version`·`source_sha256`으로 등록할 수 있다. 서버가 소유권과 실제 출력 해시를 검사하며, 24본 등 원본 임의 골격을 보존한다. 로컬 정규화·렌더는 유료 호출을 하지 않는다. 옷·헤어가 붙어 있거나 리깅이 잘못된 후보는 기준 몸 승인이 필요하며 자동 승인하지 않는다.

이미지 공장의 `body_purpose=wardrobe_base`는 대머리 두피·얼굴·손·발까지 포함한 전신에 목부터 손목·발목까지 덮는 불투명한 단색 기본복을 입힌 기준 몸을 준비한다. 기존 `whole_character`는 반팔·반바지 완성 전신 경로로 유지한다. 목적·지시문·1.20m 높이·선택 동작 ID는 작업 수락 시 고정되며 이미 수락한 작업의 지시문은 바꾸지 않는다. 새 유료 생산을 수행하기 전 대상과 횟수를 실행 화면에서 확인한다.

표준 시안도 OpenAI 응답 원문을 디스크에 먼저 저장한다. 수신 후 이미지 해석·파일 처리에서 중단되면 저장된 응답만 다시 처리하며 유료 POST를 반복하지 않는다.

## 즉시 갈아입기와 착용 저장

`NativeWardrobe`는 기준 몸 GLB를 한 번 읽고 실제 본 객체를 공유한다. 의상 GLB의 SHA-256, 슬롯, 본 이름·부모·기준 자세를 확인한 뒤 원본 본 순서·inverse bind·가중치·UV를 유지해 같은 본에 연결한다. 23본으로 바꾸거나 의상용 animation mixer를 만들지 않는다. 같은 슬롯의 새 의상은 기존 메시를 대체하고, 여러 슬롯은 모든 파일이 준비된 뒤 함께 바꾼다. 파일 오류는 기존 착용을 유지하며 빠르게 연속 선택하면 마지막 선택만 반영한다. 미사용 파츠 캐시는 두 개만 남기고 자원을 해제한다.

- `GET /api/avatar-standard/outfits/{base_id}`: 기준 몸 ID·해시, 선택한 `part_ids`, `revision`을 반환한다. 저장 전 revision은 `0`이다.
- `PUT /api/avatar-standard/outfits/{base_id}`: `If-Match`와 `Idempotency-Key` 헤더, `{base_sha256, part_ids}` 본문으로 저장한다. 승인된 같은 몸에 피팅한 파츠만 허용한다. 외형 검수 승인과는 별개이며 파츠는 `review_required`를 유지한다.
- 선택과 요청 영수증은 `avatar-standard/<owner>/wardrobes/<base_id>/selection.json`에 함께 원자 저장한다. 같은 키·본문은 원래 결과를 반환하고, 다른 본문이나 오래된 revision은 `409`로 거절한다.
- 응답이 끊기거나 성공 응답의 JSON이 잘리면 브라우저가 고정한 요청·키·revision을 보존한다. 새로고침 후 **착용 저장 결과 복구**로 같은 요청을 확인한다. 충돌 시 현재 화면의 옷을 유지하고 **저장한 착용 다시 불러오기**로 서버 선택을 가져온다.
- 즉시 교체·착용 저장에는 제공자 호출이 없다. `native-wardrobe.spec.ts`와 `wardrobe-selection.spec.ts`는 실제 Blender로 만든 폐기용 24본 몸/의상에서 동작 정점, 동일 본 참조, 교체 중 mixer 시간 보존, 응답 유실·충돌·재접속을 검증한다. 실제 유료 생산 의상의 외형 승인을 대신하지 않는다.
