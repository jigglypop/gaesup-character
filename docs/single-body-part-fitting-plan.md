# 공통 체형 1종 기반 파츠 피팅 개선 계획

작성일: 2026-09-19. 상태: 계획 수립 완료, 이 문서의 신규 구현은 미착수.

## 1. 채택할 방식

**공통 몸·골격 1개 + 의상 종류별 피팅 기준 + 생성된 파츠의 착용점 정렬**을 채택한다.

기존 이미지 생성, Meshy, 파츠별 작업, 조립, 표정 머리 교체는 재사용한다. 변경의 중심은 생성된 상·하의의 크기를 결정하는 부분이다. 체형별 자동 변환, 범용 케이지, 천 시뮬레이션은 이번 범위에 넣지 않는다.

여기서 의상 기본형은 목·어깨·소매·허리·밑단의 위치와 여유를 정의하는 피팅 데이터다. 생성된 옷의 메시·UV·주름·장식을 유지하면서 착용부와 필요한 구간을 조정한다. 모든 옷을 동일한 기본 메시로 교체하는 작업은 계획하지 않는다.

생산 흐름:

```text
고정된 몸·골격·T 자세
  → 원본 디자인 + 의상 종류별 피팅 기준
  → 같은 좌표·배율의 정면 / 측면 / 후면 이미지
  → 파츠 1개당 Meshy 작업 1개
  → 착용점으로 회전·이동·균일 배율 정렬
  → 소매 / 몸통 / 밑단의 제한된 구간 보정
  → 공용 골격 연결 + 실제 의상 경계에 맞춘 몸 가림
  → 파츠별 저장 + 기존 조립에 교체
```

피팅은 생산 시 한 번 수행한다. 같은 몸에 이미 맞춘 파츠를 착용할 때는 저장한 결과를 그대로 사용한다.

공용 골격으로 분리된 메시를 조립하고 교체하는 구조는 [Unreal 공식 모듈형 캐릭터 문서](https://dev.epicgames.com/documentation/unreal-engine/working-with-modular-characters-in-unreal-engine)의 기본 구성과도 일치한다. 엔진을 변경하자는 의미는 아니며, 현재 WebGPU 뷰어를 유지한다.

## 2. 현재 구현에서 재사용할 것과 변경할 것

아래는 현재 소스 기준이며, 구현 존재와 실제 생성물의 외형 완성은 별개다.

| 영역 | 현재 구현 | 계획 |
|---|---|---|
| 공통 몸 재사용 | `avatar_variants.py`에서 몸·골격·동작 및 원본 해시 고정 | 기본 생산 경로로 사용 |
| 몸 기준 이미지 | `avatar_body_reference_blender.py`, `avatar_production_spec.py`의 실측 앵커·정사영·미터 좌표 | 몸 프로필에 저장하고 재사용 |
| 3뷰 생산 | `avatar_multiview_images.py`, `avatar_image_pipeline.py`, `character_jobs.py`의 front/side/back 전달 | 유지, 기존 2뷰 작업은 원래 계약 보존 |
| 파츠 하나 교체 | `AvatarVariants.create_single_part`, `AvatarNativeParts.start_refit` | 생성과 로컬 재피팅 진입점 유지 |
| 다른 파츠 보존 | `native_part_reuse` / `prefit_parts` | 선택하지 않은 파츠는 저장 GLB 그대로 재사용 |
| 착용점 정렬 | `avatar_standard_blender.py:fit_matrix`의 회전·이동·균일 배율 계산 | 수학 계산을 공장 피팅에 재사용 |
| 상·하의 크기 | `avatar_fit_geometry.py:box_fit`의 XYZ별 전체 늘이기 | 신규 의상 프로필에서 착용점 정렬로 교체 |
| 소매 | `avatar_arm_geometry.py:fit_sleeves`가 모든 상의를 손목에 맞춤 | 소매 종류와 실제 끝점에 맞춰 구간 보정 |
| 스킨 연결 | `avatar_standard_blender.py:bind`, `bind_top_regions` | 유지하면서 몸통·좌우 팔다리별 대응 영역 보강 |
| 몸 가림 | `avatar_body_layers.py`의 의상 경계와 본 기준 처리 | 같은 피팅 결과의 실제 소매·밑단 경계를 사용 |
| 신발·장비 | `avatar_shoe_geometry.py`, `fit_equipment`의 발별·부착점 피팅 | 기존 별도 방식 유지 |
| 머리·표정 | `avatar_expression_heads.py`, `native-wardrobe.ts`의 머리 분리·교체 | 그대로 재사용 |
| 운영 흐름 | S3, 작업 영수증, 요청 키, 재접속·단계 재개 | 그대로 유지 |

`docs/fixed-body-avatar.md`에 기록된 착용점 정렬 구현도 재사용 대상이다. 해당 문서의 과거 화면·검수 차단·테스트 실행 지침은 이번 계획에 적용하지 않는다. 현재 진입점과 최신 AGENTS.md를 따른다. `manual-v1` 의상 파일은 존재하지만 현재 공장 몸과의 호환성이 확인된 기본형으로 간주하지 않는다.

## 3. 공통 몸을 고정하는 방법

기존 저장 몸 중 대표 몸 1개를 정하고, 새 몸 생성 없이 다음 정보를 버전으로 묶는다. 대표 몸의 최종 ID는 아직 이 계획에서 지정하지 않는다.

- 기존 `base_job_id`, `base_version`, 원본 몸 GLB 해시.
- 몸 형상·공용 골격·rest pose를 식별하는 서명, 기존 동작 목록.
- 미터 단위, 발 사이 바닥 원점, glTF X/Y/Z 방향, T 자세.
- 목, 좌우 어깨·팔꿈치·손목, 허리·골반·가랑이, 무릎·발목의 좌표.
- 몸통·골반·팔다리의 필요한 단면 치수와 머리 착용면.
- 동일 배율의 정면·측면·후면 몸 렌더 및 카메라 설정.

관절 위치는 기존 본에서 얻고, 옷 둘레에 필요한 치수는 해당 신체 영역의 메시 단면에서 얻는다. 본 좌표만으로 몸 두께를 추정하지 않는다. 기존 1.2m 단위 체계는 유지하고, 몸 비율을 XYZ별로 다시 조정하지 않는다.

표정 텍스처나 분리 머리 파일이 바뀌어도 의상 호환 몸이 바뀌지 않도록 몸 프로필 ID와 개별 표현 파일 해시를 구분한다. 골격·몸 형상이 바뀌면 새 프로필 버전이다. 이전 몸의 파츠는 이전 프로필에 남긴다.

일반 사진 생성은 이 공통 몸을 기본 선택으로 사용한다. 현재의 새 몸 생성 기능과 이미 수락된 작업은 보존한다. 몸 없는 초기 상태에서 새 유료 생성을 자동 실행하지 않는다.

## 4. 의상 피팅 기준

의상 종류와 길이를 분리해서 저장한다. 단순히 `top` / `bottom`만으로 같은 크기를 적용하지 않는다.

| 항목 | 최소 지원 기준 |
|---|---|
| 상의 소매 | 민소매 / 반팔 / 긴팔 |
| 상의 길이 | 원본에 맞춘 목 아래 밑단 위치 |
| 상의 품 | 보통 / 여유 있음, 몸통과 소매 여유를 별도 저장 |
| 하의 종류 | 기존 바지 / 치마 구분 재사용 |
| 하의 길이 | 허리부터 밑단까지의 비율로 반바지·긴바지·짧은 치마 등을 표현 |
| 하의 품 | 허리 착용부와 엉덩이·허벅지·치마 폭을 분리 |

의도한 소매·밑단 길이는 공통 좌표의 원본/생성 이미지와 저장된 종류 설정에서 얻는다. 이미지 전체 bbox는 프레이밍 참고값으로만 사용한다. 장식이나 퍼진 밑단을 몸 둘레로 오인하지 않는다.

### 4.1 생성 원본의 착용점을 확보하는 단계

목표 몸의 기준점만 있으면 피팅이 해결되는 것은 아니다. 생성된 파츠에서 그에 대응하는 위치를 찾는 단계가 필요하다.

1. 원본 GLB와 3뷰 이미지를 함께 읽고 슬롯·의상 종류를 확정한다.
2. 메시의 정사영 실루엣을 3뷰에 대응시켜 방향과 대략적인 배율을 구한다. 이때 이미지를 맞추려고 원본 GLB를 먼저 축별로 늘이지 않는다.
3. 상의는 목·좌우 어깨·겨드랑이·소매 끝·밑단, 하의는 허리·골반·가랑이·밑단의 후보를 단면과 연결 영역에서 찾는다. 치마에는 가랑이·좌우 바짓단 규칙을 적용하지 않는다.
4. 선택한 기준점과 근거를 원본 GLB 해시별로 저장한다. 개구부가 막힌 메시도 있으므로 열린 경계 검출 하나에만 의존하지 않는다.
5. 애매한 원본은 관리자 파츠 상세에서 기준점만 보정할 수 있게 한다. 일반 생성 화면에는 좌표 편집기를 추가하지 않는다. 매번 수동 입력해야 하는 구조를 목표로 삼지 않는다.

첫 구현에서는 기존 저장 상의·하의로 기준점 후보와 대응을 먼저 확립한다. 임의의 AI 메시에서 정확한 착용점을 항상 자동 추출할 수 있다고 가정하지 않는다. 대응점이 부족하면 기존 결과와 원본을 유지하고 해당 파츠의 피팅 상태만 표시한다. 다른 파츠 수신·표시를 차단하지 않는다.

### 4.2 실제 변형

- **전체 정렬:** 비공선 착용점 3개 이상으로 회전·이동·균일 배율을 계산한다. 목과 양 어깨처럼 한 직선에 가까운 점만 선택하지 않고 몸통의 추가 지점을 포함한다.
- **소매:** 어깨→팔꿈치→손목 축을 기준으로 원본 소매 길이에 해당하는 위치에 끝을 둔다. 반팔 끝을 손목으로 보내지 않는다. 소매 길이 보정이 몸통 폭을 바꾸지 않도록 영역과 부드러운 가중치를 사용한다.
- **몸통:** 목·어깨 착용부를 고정하고, 단면별 여유를 유지하며 몸통 부분만 보정한다. 주름과 장식을 몸 표면에 투영해 눌러 붙이지 않는다.
- **하의:** 허리를 먼저 고정한다. 바지는 좌우 다리와 가랑이를 구분하고 길이를 맞춘다. 치마는 통형 실루엣과 밑단을 보존하며 기존 골반 부착 경로를 사용한다.
- **스킨:** 최종 피팅 뒤 기존 가중치 전달을 실행한다. 몸통이 가까운 손에 붙거나 왼쪽 바짓단이 오른쪽 다리에 붙지 않도록 전달 대상을 신체 영역별로 제한한다.
- **가림:** 피팅에서 계산한 목·소매·허리·밑단 정보를 몸 가림에도 전달한다. 반팔을 입었을 때 팔뚝까지 감추는 문제를 함께 해결한다. 원본 몸과 벗었을 때 복원할 면은 유지한다.

기존 `fit_matrix`의 수학 계산과 오차 보고를 분리해 재사용한다. 과거의 오차 임계치에 따른 외형 품질 차단을 공장에 되살리지 않는다. 손상 파일·없는 본·퇴화 좌표처럼 계산 자체가 불가능한 입력 오류와 외형 진단값은 구분한다.

기본 보정은 기존 구간별 변형을 확장하는 수준으로 시작한다. 범용 자동 리토폴로지·케이지 변형 시스템은 추가하지 않는다. 심하게 다른 형태나 빠진 면은 피팅만으로 복구했다고 처리하지 않는다.

## 5. 이미지·저장 계약과 화면

### 이미지와 Meshy

상의 프롬프트의 현재 `cuffs at wrist anchors` 규칙을 소매 종류별 끝점으로 바꾼다. 이미지 생성과 Blender 피팅이 같은 프로필을 읽어야 한다. 정면·측면·후면 모두 같은 T 자세·배율을 사용하고, 세 이미지를 하나의 Meshy 작업에 전달하는 기존 경로를 유지한다.

프롬프트 문장 수정은 프롬프트 관리에서만 한다. 프로필의 치수·착용점은 서버가 계산하는 구조화된 입력으로 둔다. 기존 pending 요청의 프롬프트·뷰·입력 해시는 바꾸지 않는다.

### 저장할 최소 추가 정보

기존 작업·파츠 영수증을 확장하고 별도 작업 시스템이나 DB를 만들지 않는다.

| 위치 | 제안 정보 |
|---|---|
| 기본 몸 설정 | `body_profile_id`, `body_profile_revision`, 원본 몸·골격 서명 |
| 파츠 입력 | `fit_profile`의 종류·소매·길이·여유·revision |
| 파츠 피팅 기록 | 원본 GLB 해시, source/target 착용점, 균일 변환, 구간 보정값, 가림 영역 |
| 조립 계약 | 몸 프로필·피팅 프로필·기준점 revision 및 사용한 파츠 해시 |

설정·계산 모듈은 소스에 두고, 몸별 실측값·작업 스냅샷·원본·결과는 기존 S3 경로에 저장한다. 파츠 호환성은 프로필과 골격 서명으로 확인한다. 인접 작업의 비슷한 파일명을 호환 근거로 사용하지 않는다.

### 화면

- 사진 생성: 공통 몸을 기본값으로 사용. 프롬프트 편집은 추가하지 않음.
- 파츠 하나 생성: 기존 캐릭터·파츠 선택 유지. 상의/하의에만 필요한 종류 선택을 간단히 제공하고 길이·품은 기본적으로 원본을 따름.
- 관리자: 기존 캐릭터별 / 파츠별 분류 유지. 해당 파츠 상세에서만 종류·길이·품과 필요한 기준점 보정 제공.
- 기존 모델의 로컬 재피팅과 새 이미지·Meshy 생성은 구분. 재피팅은 기존 원본 GLB에서 새 버전을 만듦.
- 작업 중에는 마지막 완성 결과를 유지. 새 조립과 필요한 표정 재사용이 저장된 뒤 버전을 교체.

## 6. 구현 순서와 단계별 산출물

| 순서 | 작업 | 주 변경 지점 | 단계 산출물 |
|---|---|---|---|
| 1 | 대표 몸과 의상 프로필 계약 추가 | `avatar_production_spec.py`, `avatar_body_reference_blender.py`, `avatar_variants.py`, API 입력 | 몸 실측 스냅샷, 상·하의 프로필, 기존 요청과의 버전 구분 |
| 2 | 저장된 상의 1개를 끝까지 연결 | `avatar_fit_geometry.py`, `avatar_arm_geometry.py`, `avatar_standard_blender.py`, `avatar_native_parts_blender.py` | 원본 기준점 → 균일 정렬 → 소매/몸통 보정 → 가중치 연결 |
| 3 | 상의 가림과 하의 피팅 연결 | `avatar_body_layers.py`, 같은 native 피팅 경로 | 반팔 노출 영역, 바지/치마·길이별 피팅, 파츠별 가림 기록 |
| 4 | 신규 생성 입력과 최소 UI 연결 | `avatar_image_prompts.py`, `avatar_image_pipeline.py`, `avatar_variants.py`, `CharacterFactory.tsx`, `SinglePart.tsx`, 관리자 상세 | 같은 프로필로 생성·피팅, 파츠 하나 재피팅·생성 분리 |
| 5 | 기존 결과의 선택적 전환 | `avatar_native_parts.py`, 버전/재사용 계약 | 선택한 파츠만 새 피팅 버전으로 전환, 기존 버전 재선택 가능 |

**최초 적용 범위는 공통 몸 1개 + 저장된 상의 1개다.** 이 경로에서 원본 비율·소매·몸 가림·골격 연결이 어떻게 처리되는지 구체화한 뒤 하의로 확장한다. 다른 파츠도 한꺼번에 새 방식으로 바꾸지 않는다.

단계 2·3은 원본 메시가 남아 있으면 새 이미지·Meshy 생성 없이 적용할 수 있다. 원본에 누락된 면이나 잘못 생성된 의상 구조는 별도의 파츠 재생성이 필요할 수 있다. 헤어의 후면 누락은 이 의상 피팅 변경의 해결 범위가 아니다.

## 7. 기존 작업 보호와 완료 판단

- 진행 중 작업은 수락한 몸·입력·뷰·피팅 revision으로 끝낸다. 전환 중 최신 설정을 섞지 않는다. 현재 `refresh_fitting_spec`와 실행 계약의 적용 시점을 이 기준에 맞춰 정리한다.
- 새 프로필은 새 요청 또는 명시적인 로컬 재피팅에만 적용한다. 이미 수락된 요청을 조회·복구할 때 최신 revision 때문에 새 실행이 생기면 안 된다.
- 피팅 계약의 해시에 프로필과 기준점 revision도 넣는다. 같은 입력·요청 키에는 같은 결과를 반환하고, 변경된 입력은 새 요청으로 구분한다.
- 선택하지 않은 의상·헤어·장비 GLB와 저장 표정은 재사용한다. 전체 조립 파일은 새 버전이 될 수 있으나 개별 재사용 파츠의 바이트는 보존한다.
- 원본과 이전 결과는 남긴다. S3 저장 완료 전 새 결과를 현재 결과로 확정하지 않는다. S3 장애 시 로컬 저장으로 우회하지 않는다.
- 자동 관통·규격·동작 품질 검사와 그 검사로 인한 수신/결과 차단은 추가하지 않는다. 완료 상태는 실제 저장된 조립 산출물로 판단한다.

구현 시 허용된 확인은 프론트 `npm run build`, 백엔드 문법·패키지 빌드다. pytest·Playwright·실제 생성 검사는 실행하지 않는다. 유료 생성은 사용자가 별도로 실행을 지시한 경우에만 한다. 빌드 성공을 실제 의상 외형 개선 완료로 보고하지 않는다.

사용자가 실행해 저장된 결과를 확인할 때는 같은 몸·같은 원본 파츠의 전후 버전을 비교한다. 소매 종류·길이 보존, 목·어깨·허리 위치, 품과 주름, 반팔/반바지의 노출 부위, 다른 파츠와 표정 유지가 판단 항목이다. 이는 사용자 확인 항목이며 파이프라인을 막는 자동 품질 게이트가 아니다.

## 8. 이번 계획에서 실행한 범위
